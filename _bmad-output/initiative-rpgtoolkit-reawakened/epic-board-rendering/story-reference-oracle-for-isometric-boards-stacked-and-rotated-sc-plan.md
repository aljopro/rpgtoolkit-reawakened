# Reference oracle for isometric boards: stacked and rotated scenes

## Scope

Extend the merged 4.4 authored-fixture and independent Python oracle path with two
small, deterministic isometric board scenes. The implementation remains producer-side:
it does not modify `packages/core` and does not claim legacy pixel parity where the
normative specification chooses a Reawakened rule.

## Proposed rulings (pending owner review)

1. **Scene names and ownership.** Add `S-ISO-STACKED` (`coordType: 1`) and
   `S-ISO-ROTATED` (`coordType: 2`) under `golden/scenes/`, with both PNGs listed as
   `independent-reference`, gating, and producer `4.17` in `golden/ledger.json`.
   Evidence: `docs/spec/engine/parity-checklist.md#golden-image-oracle`, the 4.4
   schema and the ticket's producer/consumer ordering. Rejected alternative:
   classify these images as regression baselines, which would hide arithmetic drift
   despite the board and tile formulas being normative.

2. **Authored fixture placement.** Generate the minimal `.brd` files and required
   `.iso`/`.tst` assets from `docs/spec/formats/board.md#coordinates` and
   `docs/spec/formats/tiles.md#isometric-tiles` in the existing author generator,
   as flat files under `packages/core/test/fixtures/authored/` with an
   `iso-oracle-` prefix. Evidence: the 4.4 author-generator convention, the
   direct-file fixture-size gate, and G7's authored-fixture exception. Rejected
   alternative: a nested `render-oracle/` project directory, which the existing
   fixture-size test would treat as a fixture body rather than a file.

3. **Projection and draw order.** The reference uses the documented stacked and
   rotated tile-to-pixel formulas, effective rotated grid `(sizeX + sizeY)^2`,
   64×32 diamond masking, nearest-neighbour affine `iso2d` projection, and
   `(layer, projected screen-space y, drawId)` sprite order. Evidence:
   `docs/spec/formats/board.md#coordinates`, `#board-pixel-dimensions`,
   `#drawing-order-and-effects`, and `docs/spec/formats/tiles.md#reawakened-iso2d-projection`.
   Rejected alternative: reuse the 2D renderer's rectangular placement, which would
   silently produce plausible but incorrect iso images and omit the approved mask.

4. **Scene coverage.** The stacked scene covers an `.iso` tile, a projected 2D tile,
   two layers, a sprite pair, shading and ambient tint. The rotated scene covers the
   effective square grid, the same mixed tile inputs, camera clamping, and sprites
   whose projected y values exercise strict depth ordering. Evidence: ticket 4.17,
   the epic's handoff table, and the formulas above. Rejected alternative: one scene
   with a single tile, which would not prove either layout's traversal, sprite order,
   or clamp-sized board dimensions.

## Implementation

- Extend `tools/fixtures/author/generate.mjs` with a self-contained board writer and
  generated iso-oracle project assets; keep all generated bytes deterministic.
- Extend `tools/fixtures/reference/SCHEMA.md` and `render.py` with an explicit layout
  field, board geometry validation, diamond compositing, ordinary 2D-on-iso projection,
  camera clamping, and projected sprite ordering.
- Generate the two scene JSON files and decoded RGBA PNGs, and add ledger rows.
- Add focused renderer tests only if the existing gate has no coverage for malformed
  iso scenes or decoded-pixel regeneration; do not import `packages/core`.
