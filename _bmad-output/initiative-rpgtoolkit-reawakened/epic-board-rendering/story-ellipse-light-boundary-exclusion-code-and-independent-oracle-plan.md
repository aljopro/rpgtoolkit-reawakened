# Ellipse light boundary exclusion: code and independent oracle

## Scope

Align core `ellipseWeight` (`packages/core/src/render/shade.ts`) and the independent Python oracle (`tools/fixtures/reference/render.py`) with the round-7 rule in `docs/spec/engine/display-input-audio.md#reawakened-light-and-raster-arithmetic` (facts-round-7.md Q8): the ellipse boundary is excluded; only pixels with normalized elliptical radius strictly below 1 are lit. The single final clamp is unchanged.

## Proposed rulings (pending owner review)

1. **Exact integer strictness test.** Inside means `dx²·ry² + dy²·rx² < rx²·ry²` (zero-radius axes: `d < r` along the other axis). Both implementations carry this test independently; the old `distance > FIXED` float/trunc test is removed, and the weight formula is unchanged. Evidence: spec "no floating-point edge test". Rejected alternative: `distance >= FIXED` on the truncated fixed-point distance, which would also drop interior points whose truncated distance equals FIXED.
2. **Golden PNG changes: none.** All five existing S-LIGHT-* PNGs regenerated byte-identically: the lights' boundary points never fall on a 32×32 cell centre (the oracle samples cell centres only), so no pixel changed and no `hash-vectors.json` row changed. Evidence: regeneration produced no diff. The unit-test fixture in `shade.test.ts` did land on the boundary and its expectation changed deliberately (edge-colour -> unlit).
3. **New gating scene `S-LIGHT-BOUNDARY`** (ledger producer 4.34, independent-reference): ellipse centre (112,80), radii 96×64, so cell centres (208,80) and (112,16) lie exactly on the boundary and must stay unlit. Without it the rule would have no oracle coverage. Rejected alternative: moving existing scene lights, which would change the other five goldens needlessly (G5).
