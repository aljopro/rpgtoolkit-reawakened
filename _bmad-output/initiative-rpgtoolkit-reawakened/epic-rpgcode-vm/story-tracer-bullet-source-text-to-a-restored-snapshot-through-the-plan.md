## Intent

**Problem:** nothing in `packages/core` can run RPGCode. Models, readers and the port contracts exist (epic 1 and 2), but there is no VM, no state tree, no built-in seam and no snapshot contract, so the harness can only drive a fake `Engine` and every later entry of epic 3 (registry, grammar, classes, errors, threads, snapshot hardening) plus epics 4–8 wait on shapes that are still undefined.

**Approach:** drive one inline program the whole way once — source text → lex/parse the minimal TK3 subset → linear Step IR → provisional built-in registry (`end`, `sleep`) → the step machine yielding one AD-9 `sleep` wait and waking on the tick counter → a mid-run snapshot restored into a fresh VM → a VM-backed `Engine` test host in `runner-harness` that the existing `runLog`/golden driver drives. Ship, with it, the `GameState`/`VmState` shell (AD-10), `core/rng` (AD-12) and a reusable snapshot→restore→hash check.

**Always:** G1 — explicit step machine, statuses never promises, all VM state plain data (`AssertPlainData<GameState>`); G2 — `core` imports nothing outside `core`, `runner-harness` imports only the `@tk-reawakened/core` entry (no deep paths, AD-22); G3/AD-13 — no `Date`/`performance`/`Math.random`/`Intl` in `core`, `Math.imul` is the only `Math` member the RNG needs; AD-2 — the simulation unit is the tick (60 Hz, an assumption kept), the injected clock **is** the tick counter and `core/time` alone converts seconds; AD-7/AD-10 — the state shapes are exactly the ones AD-7 lists and each section has one owner, with the sections entry 2 does not own left empty; AD-8 — `end` and `sleep` are ordinary `BuiltinSpec`s with no VM backdoor; AD-11 — snapshot and hash use `canon`/`hashState`; ADR 0004 decision 1 — three-tier lowering (Unified AST → Step IR → registry dispatch); G7 — cite `docs/format-spec.md` §9.2/§9.3/§9.5/§9.11/§9.15/§9.16 and `docs/adr/0004` in every new core file's header, and never open the legacy tree; house style — kebab-case files, `erasableSyntaxOnly` (no `enum`, no parameter properties), `verbatimModuleSyntax` (`import type`), every new field explicit (`null`, never `undefined`).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Program runs to the end | IR falls off the end / `end()` then `return` | thread `finished`; `advance` keeps counting ticks | none |
| Blocking call | `sleep(n)` runs at tick `T` | thread `waiting`, `wait = { kind: 'sleep', until: T + n }`, `ip` already past the call, no value pushed | none |
| Wake | waits phase at a tick where `time.tick >= until` | `status: ready`, `wait: null`, the polled `value` pushed, waiting threads polled in ascending id order | none |
| Wake is early | waits phase at `time.tick < until` | `null` from poll: thread stays `waiting`, nothing pushed | none |
| Unknown command | `call` of a name no spec defines | `ScriptError` code `unknown.command` | throws for now; §9.8 (ERR-2) rules a catchable runtime error whose call result is the unset value, whose program continues with the next VM step and whose report also reaches the host as a diagnostic — entry 7 replaces the throw |
| Wrong argument count | more or fewer args than `ParamSpec[]` allows | `ScriptError` code `arity.mismatch` | throws for now; §9.8's report-and-continue is entry 7's |
| Bad sleep count | `sleep(0)`, a fraction or a negative count | `ScriptError` code `builtin.bad-arg` | throws; the `0`-means-indefinite case and the seconds→ticks formula are `threadSleep`'s (§9.15, THR-1; entry 9) |
| By-reference output | built-in returns `out: [[i, v]]` for `params[i].byRef` | the caller's variable holds `v` before the next VM step and inside the state hash | `out` for a non-`byRef` param → `ScriptError` code `builtin.out-not-by-ref` |
| Snapshot | any `GameState` | `canon` round-trips exactly: `canon(restoreGameState(canon(s))) === canon(s)` | different `schema.compiler` → `ScriptError` `restore.compiler-mismatch`; a missing section → `restore.shape` |
| Unset variable read | a name never assigned | `0` — the numeric default; §9.16 (SEM-5) rules the whole unset value (numeric 0, the empty string in string context, create-on-read) and its code lands with entry 12 | none |
| Empty batch | `advance(0, [])` | `ticksRun: 0`, `tickAfter` unchanged, state hash unchanged | none |
| Non-inline program | `ProgramRef { kind: 'file' }` | `ScriptError` code `program.file-unsupported` | throws (entry 8 loads files) |
| Second blocking thread | a blocking thread already exists (AD-26) | `ScriptError` code `thread.blocking-exists` | throws |
| Inputs offered | a non-empty input log | `consumed: []` — nothing consumes inputs yet; the driver reports the mismatch itself | none (documented, not silently swallowed) |

## Design Notes

**The tracer program** (the golden example; one statement per line, §9.2/§9.5):

```
greeting = "hi"
count = 2
sleep(count)
count = 3
end()
```

Its tick trace, with `advance(1, [])` = one whole tick (`waits → threads → time`) and `time.tick` starting at 0: tick 0 runs `push "hi"`, `store greeting`, `pop`, `push 2`, `store count`, `pop`, `load count`, `call sleep 1` → yields, `ip` past the call, `wait = { kind: 'sleep', until: 0 + 2 }`; tick 1 polls and stays waiting; tick 2 wakes it (the polled `null` is pushed, then popped), stores `count = 3`, calls `end` and hits the `return`, so the thread is `finished` when `time.tick` reaches 3. The mid-run snapshot is therefore taken after tick 0 or 1, and the fresh host runs the remaining ticks to the same hash. `wait.until` is `T + n` with `T` the tick in progress when the call ran and `n` whole ticks — exactly §9.15 (THR-1)'s end tick, so the wait is a one-field absolute value and a snapshot needs nothing else.

**Step IR** (ADR 0004 decision 1's linear array; entry 5 extends the union):

```ts
export type StepOp =
  | { op: "push"; value: Value }                 // literal; §9.2 true/false/null lex to 1/0/0
  | { op: "load"; name: string }                 // variable read (locals, then globals); unset → 0
  | { op: "store"; name: string }                // pop and assign (write-back is entry 3's `out`)
  | { op: "call"; name: string; argc: number }    // pop argc args, dispatch, push the result
  | { op: "pop" }                                // discard a statement-position value
  | { op: "return" };                            // end the program; the lowering always emits it last
```

The kinds map to ADR 0004 decision 1's names (`push` ≙ `OP_PUSH`, `call` ≙ `OP_CALL`, `return` ≙ `OP_RETURN`); `load`/`store`/`pop` are this entry's additions for variable access and for discarding a statement-position value, and `jump`/`yield` are deliberately absent: `OP_JUMP` needs control flow (entry 5) and a blocking call *is* the yield (AD-8 makes yielding a call outcome, not an opcode) — see Q11. Each op is one VM step in §9.15 (THR-3)'s sense, so `STEP_BUDGET` counts `StepOp` executions.

**The frontend subset.** IN: identifiers `[A-Za-z0-9_]` with a trailing `!`/`$` sigil stripped and ASCII case-folded (§9.2 — `N` and `n` are one variable); decimal and fractional numbers; `"strings"` with no escapes; `(`, `)`, `,`, `=`; a statement ends at a newline or `;`; `//` comments; a leading `#` on a line ignored; `true`/`false`/`null` as the literals 1/0/0; a bare identifier alone on a line as a zero-argument call (§9.5's legacy `end` → `end()`); assignment to a variable; a call with literal or variable arguments. OUT, each rejected with a `ScriptError` naming the construct and its entry: every other operator (§9.4, entry 5), `if`/`while`/`until`/`for`/`switch`/`function`/`method`/`class`/`label`/`return` (entry 5/6), `local(x) = v` and `global(x) = v` (FUN-2, entry 5), arrays, indexes and maps (entry 5/12), `_` line continuation and `/* */` (entry 5), `#include`/`include()`/implicit includes/`redirect` (now ruled in §9.6; entry 8 implements them), the §9.9 legacy forms and TK2 (entry 15). The tracer's program uses only the IN list, so entry 2 does not depend on entry 1's rulings (the ticket's `after` is `1.3`, `1.8`, `1.9`).
**Corrections from the §9.12 rulings (added after entry 1 landed).** (1) LEX-3: a `!` directly followed by `=` is the not-equal operator, never a sigil, so the lexer strips a trailing `!`/`$` only when no `=` is adjacent; `x!=1` is the operator (OUT, entry 5) and `x! = 1` (spaced) keeps the sigil reading. (2) LEX-6: `#include` is the one directive 3.1 reads, so the lexer recognises it by name (case-insensitive, optional space after `#`) and rejects it with `ScriptError` naming entry 8; every other leading-`#` line is ignored legacy. (3) `/* */` comments and the `_` line continuation (LEX-1) are OUT and rejected by name; entry 5 extends the lexer for them. (4) `Thread.source`/`target` stay per-thread: §9.15 (THR-2) has now ruled the pair per-thread and in state, which is what AD-7 already lists, so no AD-7 amendment is needed; a plain thread has `null` for both, and the `"source"`/`"target"` handles and `sourceHandle()`/`targetHandle()` (returning `0` when a slot is `null`) are entry 9/13's reads.

**State shapes (AD-7's minimum, with the values entry 2 fixes).** `VmState = { threads: Thread[]; globals: { [name: string]: Value }; objects: never[]; redirects: Array<[string, string]> }` — `objects` is entry 6's and `redirects` entry 8's, both empty now. `Thread = { id: number; kind: ThreadKind; owner: ThreadOwner; source: string | null; target: string | null; frames: Frame[]; status: ThreadStatus; wait: Wait | null }` with `ThreadKind = 'blocking' | 'board' | 'persistent' | 'item'` (AD-26), `ThreadOwner = 'script' | 'world'` (AD-26), `ThreadStatus = 'ready' | 'waiting' | 'finished'`. `Frame = { program: ProgramRef; ip: number; locals: { [name: string]: Value }; operands: Value[]; errorHandler: null; autoLocal: boolean }` — `errorHandler` is entry 7's and is `null` until then. `GameState` has exactly AD-10's 18 sections; every section entry 2 does not own is `Record<string, never>` (the empty-object placeholder), with a comment naming its owner module and the entry that replaces the alias. `ScriptStatus = 'running' | 'waiting' | 'finished'` is what `advanceScriptTick` returns; it is not `Thread.status`.

**Built-in seam (provisional, AD-8's shape):**

```ts
export type ParamSpec = { readonly name: string; readonly optional: boolean; readonly byRef: boolean; readonly variadic: boolean };
export type Arg = { readonly value: Value; readonly ref: RefId | null };
export type BuiltinResult = { readonly done: Value; readonly out: readonly (readonly [number, Value])[] } | { readonly yield: Wait };
export type BuiltinCtx = { readonly rng: RngPort; readonly clock: ClockPort };
export type BuiltinSpec = { readonly name: string; readonly aliases: readonly string[]; readonly params: readonly ParamSpec[]; readonly call: (ctx: BuiltinCtx, args: readonly Arg[]) => BuiltinResult };
```

`PROVISIONAL_BUILTINS` is exactly `end` (no params, `done: null`) and `sleep` (one required tick-count param, yields `{ kind: 'sleep', until: ctx.clock.tick() + n }`). `end` returning normally is deliberate: it proves registry resolution and the dispatch path, while `end`/`done`/`stop`'s real unwinding (FUN-7) is entry 13's, and the AD-8 assembly, aliases, duplicates, warnings and precedence are entry 3's — Q1. `resume?` is not implemented (no resuming built-in exists yet; waking a yielded call is generic).

The `sleep` payload is the absolute `until` tick, not a relative duration: the poll is then `view.tick >= wait.until` with nothing else in state, whereas a duration would need the tick the wait started at, which is a new `Thread` field and an AD-7 amendment. `sleep` is provisional and **not** `threadSleep`: it takes whole ticks directly, so it applies neither THR-1's seconds→ticks formula (that is `core/time`'s `secondsToTicks`, for `threadSleep`, entry 9) nor the `0`-means-indefinite rule; a `0`, fractional or negative count is a `builtin.bad-arg` `ScriptError` (the matrix's "Bad sleep count" row). `threadWake`, `tellThread` (queued, not immediate — THR-2) and `threadSleepRemaining` are entry 9's.

**Snapshot semantics.** `snapshot(state) = canon(state)` and `restoreGameState(json) = JSON.parse` plus a compiler-version and section-presence check — one canonical form for snapshot, save, hash and restore (AD-10/AD-11), which also makes the plain-data discipline enforceable (`canon` throws on `undefined`, `NaN`, a sparse array or a class instance). Compiled programs are rebuilt from `ProgramRef` on restore (AD-7), so a fresh host recompiles lazily through its own `ProgramLookup`; the registry is code, not state, so `restoreScriptHost` takes the same `builtins` list.

**The host is not the engine.** `ScriptHost.advance` loops `advanceScriptTick(state, services, STEP_BUDGET)` once per requested tick and reports the state hash; it holds no phase list, no game logic and no world. Epic 4's `createEngine(init)` will own `RunConfig` (including `seed`), the AD-26 phase list and the loop, and call `runWaitsPhase`/`runThreadsPhase` in its own order with the registry from entry 3 — Q6.

**Rulings this tracer touches (reconciled 2026-10-12).** §9.6, §9.8 and §9.15–§9.17 and the §9.14 follow-ups were ruled after this plan was first written; the tracer's slice of each:
- **§9.15 THR-1 (the sleep and its unit)** — the wait stores the absolute end tick `T + ticks`; the seconds→ticks formula `max(1, floor(seconds * 60 + 0.5))`, `0`/`-0` meaning indefinite and the negative/non-finite error belong to `threadSleep` (entry 9), not to the provisional `sleep(ticks)`. The tracer's `core/time` does not implement `secondsToTicks` yet (task above).
- **§9.15 THR-2 (source/target)** — per-thread, in state, `null` for a plain thread; the tracer sets both to `null` and implements neither `tellThread` nor the handle reads.
- **§9.15 THR-3 (step, budget, wake order)** — a *step* is one VM instruction (`a StepOp`); `STEP_BUDGET` counts VM steps per thread per tick and stays provisional; a waiting thread spends no budget; the waits phase polls in ascending id before the threads phase, so a thread that wakes runs in that same tick and spends that tick's budget. All four are the tracer's behaviour.
- **§9.16 SEM-6 (by-reference write-back)** — outputs are resolved by the ordinary scope rules, created if missing and written left to right in parameter order: the tracer's `Arg.ref` is that resolution captured at bind time and `runThreadsPhase` applies `out` in index order. SEM-3 (number formatting, the `ToInt32` name-read truncation) and SEM-4/SEM-5 (the scope order, parameters, members, create-on-read) are entries 5/6/12's; the tracer needs only single-name `load`/`store` and the numeric default `0`.
- **§9.8 (errors)** — a catchable runtime error is reported and the program continues with the unset value; the tracer has no handler slot or report path, so it throws a `ScriptError` and entry 7 converts that to the ruled path (the matrix's two "throws for now" rows).
- **§9.6 (modules) / §9.17 (classes)** — wholly entry 8's and entry 6's; the tracer rejects their syntax by name and leaves `redirects` and `objects` empty.
- **§9.14 follow-ups** — (5) `ProgramRef`'s run-time include list and (6) the redirect-aware compiled-program cache key are entry 8's; (7) `GameState` carries no VM-step counter, so the shared restore check counts the host's unit (a tick) and no per-VM-step comparison is added — Q12. ADR 0004 decision 1's TK2 `<>` sentence (follow-up 1) and AD-2's now-ruled assumption (follow-up 3) are docs fixes outside this entry.

## Open Questions

Recommendations are what the implementer adopts if the plan is approved as written; each is a human ruling at this ticket's plan checkpoint.

1. **`end()` unwinding.** **Ruled (a) by Jensen, 2026-10-12:** `end` is an ordinary registered call that returns `null` and the program finishes at its emitted `return`; the tracer's acceptance reads "ran to completion". `end()` must still unwind fully (format-spec §9.5, FUN-7, R2-Q20: immediate, abandons every pending frame, `run()` ends its caller), and entry 13's verify now requires that, including nested calls, includes and `run()`. Options were: (a) as ruled; (b) invent a termination channel now (`{ end: true }` or an effect record) so `end()` can stop mid-program. (b) was rejected because it invents contract surface that entry 3 (assembly, functional command contract, effect records) and entry 13 own, and ADR 0004 decision 2 forbids a backdoor for a specific name.
2. **Where the state tree lives:** `core/save` (which AD-10 makes the owner of `schema` and of `SaveState`-is-`GameState`) or a neutral `core/state` composer. **Recommendation: `core/save`** — the structural seed in the spine lists `save/` and no `state/`, and `schema` plus the snapshot/save/hash/restore functions are the save module's per the table. The composer necessarily imports each owner's section type, which AD-10's future dependency-cruiser rule ("only `core/<section>/**` imports its mutable `<Section>State`") must exempt; record that exemption when the rule lands.
3. **Placeholder for unowned sections:** one uniform `Record<string, never>` alias per section (empty until its owner lands) versus leaving the section out of `GameState` until its owner adds it. **Recommendation: the placeholder alias** — AD-10 says `GameState` has exactly those sections, entry 2's job is the shell that entries 6/7/9/10 fill and 11 reconciles, and an empty record is plain data that hashes, so the section set is visible from day one and a wrong slot cannot creep in silently.
4. **Snapshots as text:** `canon` string versus a structured clone object. **Recommendation: the `canon` string** — AD-10/AD-11 say one canonical form for snapshot, save, hash and restore, `canon` rejects anything outside `PlainData`, and equality is then string equality. Bounds, deep validation and the mismatch-versus-restart policy stay entry 11's.
5. **The shared restore/hash helper's home:** `runner-harness` versus a test-only module in `core`. **Recommendation: `runner-harness`** — G2 forbids `core` importing a runner, so a core test-only copy could not be shared with the corpus/golden consumer, and the helper plus its host is the harness's job (its verifies are named in entries 6/9/10/11 and 17). Later entries whose checks live in `core/test/` use `snapshot`/`restoreGameState`/`hashState` directly, which are the same primitives.
6. **Who owns the script-phase tick and the budget constant:** `core/script` now versus waiting for epic 4's `core/engine` (AD-26's phase list). **Recommendation: `core/script/vm.ts` exports `advanceScriptTick` (waits → threads → `time`) and `STEP_BUDGET`**, epic 4 owns the phase *list* and the loop and calls the two phase handlers, and entry 9 tunes the budget — the tracer needs a runnable tick now, and this keeps the host free of sequencing so epic 4 supersedes it rather than rewriting it.
7. **`RefId` shape:** a branded string (`"global:name"`), a `{ scope, name }` object, or a numeric index into a per-frame lvalue table. **Recommendation: the branded string** — plain data, no extra `Frame` field (so no AD-7 amendment), self-describing in a snapshot, and string ids are already house style (the `"source"`/`"target"` handles of §9.10, `AssetKey`). The lvalue table would need a new state slot and a schema bump.
8. **The provisional `sleep` name and unit:** `sleep(ticks)` in whole ticks versus a legacy name with seconds. **Ruled by Jensen, 2026-10-12: ticks.** A tick is one fixed simulation update (AD-2, 60 Hz, an assumption kept); the unit is ticks, not seconds — and entry 3.26 (PR #45) has since renamed the whole simulation unit from step to tick, so the spine, the ports and this plan now agree (`advance(ticks, inputs, maxTicks?)`, `ticksRun`, `tickAfter`, `time.tick`, `DrawList.tick`, `InputRecord.tick`, `TickRecord`). Rationale: it matches the AD-9 kind it yields, it keeps the seconds→ticks conversion out of entry 2 (AD-2 says `core/time` alone owns `secondsToTicks`, whose rounding §9.15/THR-1 now rules, and entry 13's `delay`/entry 9's `threadSleep` are the legacy spellings, in seconds), and the ticket names `sleep` explicitly. The provisional piece is throwaway in the sense that entries 3/9/13 replace its callers, not its contract. `step` survives only where it means the VM's own instruction (§9.15/THR-3): Step IR/`StepOp`, `STEP_BUDGET`, "step budget".
9. **Public surface:** exporting the host and the helper from `runner-harness/src/index.ts` (and updating the pinned surface test) versus keeping them internal-only. **Recommendation: export** — the ticket's verify says the program is run "through a VM-backed test host in `runner-harness`", entry 4 supersedes it from another package, and later entries and the corpus job reuse `checkSnapshotRestore`; `createTestEngine` stays unexported.
10. **Plan size:** the workflow's target is 900–1600 tokens and this plan is larger, because the assignment for this ticket asks for the file list, the type shapes, the exact test list, the open questions and the risk list in one plan. **Recommendation: keep the full plan** — the tracer is one user-facing goal (nothing here can be merged as an independent shippable slice without ceasing to prove the seam), and the detail is what stops the implementer re-deriving contracts that entries 3–11 must keep.

11. **Does the IR need an explicit `yield` opcode?** ADR 0004 decision 1 lists `OP_YIELD` in the Step IR, while AD-8 and AD-9 make yielding the result of a built-in call. Options: (a) the union stays as Design Notes writes it and a blocking call is the only yield — nothing in the language emits a bare yield, so an `OP_YIELD` instruction would be dead code; (b) add `{ op: "yield" }` now so the union matches ADR 0004's list literally, and let entry 5/9 decide what lowers to it (for example the program-level yields `run` and `multiRun` need). **Recommendation: (a) for entry 2, and record the reconciliation as a doc fix** — the entry that first needs a program-level yield (entry 9's `multiRun`/`run`, or entry 5) adds the opcode and amends ADR 0004 / AD-8 in the same change; adding a dead opcode now would be an untested instruction in a state machine whose whole point is testability. If the human prefers (b), say so and the union gains `yield` with a lower-to-nowhere test.

12. **Which unit does the shared snapshot-restore check count?** §9.15 (THR-3) defines a snapshot "step" as one VM instruction and says a test comparing "the same state hash after N steps" counts VM steps; the epic and the ticket call it a "random-step snapshot", yet the plan's helper drives an `Engine` (whose only advance unit is the tick) and compares `TickReport.stateHash` after each host advance. Options: (a) the helper counts the host's advance unit, i.e. **ticks** (the tick-split reading); (b) it counts VM steps, which needs a new one-VM-step advance on the host and a VM-step counter that AD-10 does not have (§9.14 follow-up 7). **Recommendation: (a)** — the ticket and the epic were written on 2026-10-11, before entry 3.26 renamed the simulation unit (2026-10-12), so "random step" there means a random **simulation** step, i.e. a tick; the tracer's host and snapshot boundary are per tick; this plan's own three splits come from the tracer's three ticks and from `runLog`'s `{ ticks: 3 }`; and (b) would add state and an AD-10 amendment that follow-up 7 assigns to the entry that adds per-VM-step comparisons, not to this one. If the human prefers (b), the tracer grows a VM-step counter and a one-step advance, and both are recorded as part of this ticket.

## Risks

1. **Provisional code that later entries replace** (the frontend subset, the registry, `sleep`, `end`'s result, the throwing error path). Mitigation: each provisional piece sits in one file with a header naming the replacing entry (3, 5, 7, 9, 13), nothing reaches into its internals, and the AD-8/AD-9 contract shapes are matched now so entry 3 replaces assembly, not contract.
2. **The language rulings are settled.** Entry 1 landed LEX-1..11, EXP-2..6, STX-4..7, FUN-5..7 and PRG-1..2 in format-spec §9.12, and the rows it deferred are now ruled too — OOP in §9.17, ERR in §9.8, MOD in §9.6, THR in §9.15, SEM in §9.16; only SEM-1 and SEM-2 stay deferred to entry 3.12's own docs commit. The IN/OUT table must match §9.12 (see the corrections after The frontend subset); a later change to a ruling means entry 5, which owns the grammar, re-derives the frontend.
3. **State-shape churn.** Entries 6/7/9/10 widen `VmState`/`Frame` and entry 11 reconciles; AD-7's check requires a schema or compiler bump plus a previous-version fixture. Mitigation: entry 2 seeds `schema`/`SCHEMA_VERSIONS` and documents the bump rule in `save/state.ts`.
4. **AD-10's dependency rule could flag the composer** (`core/save` importing every section type) and the VM's read of the tick counter. Mitigation: the composer is the documented single exemption (Q2), and the VM sees time only through `ClockPort`/`WaitView.tick` and mutates it only through `core/time`'s `runTimePhase`.
5. **The host could grow into a second engine.** Mitigation: no phase list, no game logic, no world in the host; it calls `advanceScriptTick` and reads hashes, and epic 4 supersedes it by calling the same registry and phase handlers.
6. **Determinism traps in the new code:** `Math.imul`/`>>>` only in the RNG, integer tick maths only, no `Date`/`performance`, and `canon` throws on `NaN`, sparse arrays or `undefined` (it normalises `-0` to `0`), so the plain-data assertions must run at build time (the fixture update covers it).
7. **Lint/provenance traps:** no `enum` or parameter properties (`erasableSyntaxOnly`), `import type` everywhere (`verbatimModuleSyntax`), no legacy identifiers in fixtures or code (the provenance scan covers `.ts` and `.json`; `_bmad-output/` is out of scope but the code is not), no `Promise`/`async`/generator/`await` under `core/src/script/**`.
8. **The golden job must stay green**, which means no `golden/**` edit and no emission of `requests`, `diagnostics` or `paused` from the host, and no audio cue sent to the sink — `runLog` throws on non-empty `requests`/`diagnostics`, a non-null `paused`, `loading`, and on a `ticksRun`/`tickAfter`/`consumed` mismatch.
9. **Test-harness conventions:** `node:test` with `node --test "packages/*/test/*.test.ts"`, `.ts` import suffixes and no skipped tests (the no-skips job); `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` mean every new state/port type has explicit `| null` fields and every indexed access is checked.
10. **Scope creep around the seam:** `runner-headless`'s `.prg` skip, the dump corpus and the golden wiring belong to entry 17/19 — leave them; the plan's only public-surface change outside `core` is the two new harness exports and the pinned-list update.
