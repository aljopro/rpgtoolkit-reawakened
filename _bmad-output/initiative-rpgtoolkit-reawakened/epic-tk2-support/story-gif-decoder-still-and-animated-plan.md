## Intent

**Problem:** GIF is the second picture format of the Toolkit 2 era and the only one that can be an animation. `docs/format-spec.md:1403` rules it **"Owed a reader, and not only for a still frame: §7.2 lets an animated GIF replace an `.anm`, so the reader must yield every frame and its delay"** — 520 files in the 25 community games, 58 in four of the six TK2 games, 232 script references — and `docs/format-spec.md:1407` says the rebuild "adds BMP and GIF readers". The modern spec agrees (`docs/spec/formats/README.md:118`), and `docs/spec/formats/animation.md:32` already carries the owner's R-10 ruling that an animated GIF adopted as an animation takes **one delay from the first page, the size from the first page, and its transparent colour from the background colour (magenta if absent)**. `core` has no GIF reader: `packages/core/src/formats/image/index.ts:57-71` dispatches PNG, JPEG and BMP only, `packages/core/src/formats/registry/core-decoders.ts:245-250` claims `png`/`jpg`/`jpeg`/`bmp` and no `gif`, and `packages/runner-headless/src/dump/formats.ts:74` skips every `.gif` with "no decoder in core yet". So no TK2 game that ships a GIF can load, no board or sprite art stored as a GIF resolves, and the epic's Done-when 1 (0 failures, 0 residue) cannot be reached.

**Approach:** Add `packages/core/src/formats/image/gif.ts` behind the one texture entry `decodeTexture` (AD-28) for the still case, and behind one new entry `decodeGif` that returns a GIF's **pages with their delays** for the animation path (§7.2, E-54 at `docs/spec/engine/plugins-and-battle.md:172`). Dispatch it by the `GIF8` signature and the `gif` extension, register it in the image decoder of the core format registry (AD-31), and move the dump's `.gif` row from skipped to parsed. The reader is hand-written pure TypeScript — an LZW decoder, a four-pass de-interlacer, global and local colour tables, and the graphic control extension — with no new dependency (G2, G6). Because `docs/` states GIF's ruling but nowhere its layout (`grep -ic gif docs/spec/formats/images.md` is 0), the first commit is doc-first (G7 rule 4, `docs/guardrails.md:125`): a GIF section in the normative spec, written from the public GIF87a/GIF89a format and checked against the archive's own files, before any code.

## Boundaries & Constraints

**Always:** Implement from the new docs section; write that section first, in its own commit, and cite it from the code. Return straight RGBA, top row first, `w × h × 4` — the file's own colours, and a transparent index rendered as that palette colour with alpha 0 (the same shape the PNG `tRNS` path gives, `docs/spec/formats/README.md:105`). Return a located `FormatError` (path, offset, section, message) and never throw (AD-18); take the 100,000,000-pixel refusal and the refusal-before-allocation contract from the shared §10.1 rule. Check every untrusted count — the screen size, each page's rectangle, the sub-block chain, the LZW codes — against the bytes that remain before reserving anything, the way `docs/spec/formats/README.md:63` requires and `bmp.ts:138-141` does. Keep `core` free of DOM, Node, I/O and timers (G2) and add no runtime dependency (G6). Exercise the decoder with committed authored fixtures, hand-built byte arrays and a throwaway cross-check against the archive, and leave the real-corpus digests to 16.9.

**Never:** Apply a colour key, premultiply, or approximate a page. Change `golden/legacy-corpus.json`, or run `pnpm dump:record` / `pnpm golden:record` (G5). Commit a game from the fetched corpus or from the local archive. Touch `docs/format-spec.md` (ADR 0007 decision 6: nothing is added to it) or `docs/spec/formats/animation.md` (R-10 is already stated there). Implement a GIF *writer* (T-32's export is the editor's, not this entry's). Add a runtime dependency, or widen `packages/core/dependency-allowlist.json`. Read `../rpgtoolkit` (G7).

| Clear code mid-stream | hand-built | The table resets and the width returns to the minimum plus one | — |

## Code Map

**The ruling (what GIF is to the project).** `docs/format-spec.md:1403` — the GIF row of the §10.4 table: "**Owed a reader**, and not only for a still frame: §7.2 lets an animated GIF replace an `.anm`, so the reader must yield every frame and its delay". `docs/format-spec.md:1407` — "The rebuild … adds BMP and GIF readers as above". `docs/format-spec.md:1328` and `:1334` — the §10 table row and the colour-key/animation sentence this decoder serves. `docs/spec/formats/README.md:118` — the same ruling in the normative spec: "owed a reader, and it must yield every frame and its delay, because an animated GIF stands in for an `.anm`". The ruling was made by ticket 2.19, whose entry (epic-legacy-formats, id 19) is done.

**The animation contract to serve.** `docs/spec/formats/animation.md:30-32` — an animation name ending `.gif` takes its frames from the GIF's pages, "the size comes from the first page, the delay from the first page's frame time, and the transparent colour from the first page's background colour (magenta `(255, 0, 255)` if absent)", marked **Reawakened rule (R-10)**, owner-ruled in `discovery/docs-spec-reconciliation.md:52`, with 16.12 named as the decoder's owner. `docs/spec/engine/plugins-and-battle.md:172` (E-54) — an animation frame is "a per-frame image, a per-frame transparent colour, a per-frame sound and a frame delay in seconds". The `.anm` model keeps one `delay` for the whole animation and a per-frame `transparent` colour (`packages/core/src/formats/animation/model.ts:23-64`), and `Colorref` is `{r,g,b}` (`packages/core/src/formats/binary/color.ts:8-16`) — so `decodeGif` returns per-page delays **in seconds** plus R-10's one colour, and the animation path applies them.

**The layout (what no document states today).** `grep -ic gif docs/spec/formats/images.md` is 0: the page documents BMP only, and nothing under `docs/spec/` or `docs/format-spec.md` gives GIF's header, screen descriptor, colour tables, LZW stream, interlace passes or control extension. GIF87a/GIF89a is a public format (the CompuServe specification, published 1987/1989), so the section is authored from that public layout and cites the archive's files as its evidence — ADR 0007 decisions 2 and 3. Nothing comes from the legacy source, so no ADR 0006 extraction round applies.

**The docs target.** `docs/spec/formats/images.md:1-3` — the page title and the intro sentence ("one of three kinds: PNG, JPEG or Windows bitmap"), which gains GIF. `:7-17` — "The shared decode contract", whose signature list gains `GIF87a`/`GIF89a`. `:18-104` — the BMP material, to be wrapped under a `## Windows bitmap (`.bmp`)` heading **keeping that text**, so the anchor `#windows-bitmap-bmp` cited by `docs/spec/formats/README.md:117` and `packages/core/src/formats/image/bmp.ts:2` still resolves (a heading's anchor comes from its text, not its level). `:105-107` — "Evidence", extended with the GIF census. `docs/spec/formats/README.md:24` — the index row for images; `:105-109` — the "Decoding — Reawakened rule" sentence (signature list) and the per-format bullets; `:115-119` — the image-kind table whose GIF row (`:118`) flips from "owed a reader" to **Decoded**. `docs/spec/formats/README.md:59-61` — "Counts are usually upper bounds", the convention the new page distinguishes GIF's fixed-size fields from.

**The corpus, measured 2026-10-15 (read-only, `~/projects/rpgtoolkit-archive`).** 1878 files carry a `.gif` name; **1632 are real GIF bytes** (the other 246 are Wayback error pages saved under a `.gif` name). Those 1632 are **292 GIF87a and 1340 GIF89a**, holding **4186 pages**: 1447 single-page files and 185 multi-page, 284 interlaced pages, 708 pages with a local colour table, and 296 files with **no** global colour table — every one of which carries a local table on every page. LZW minimum code sizes are 2 to 8 with nothing outside; the code width reaches 12 bits in 1078 pages, 11 in 666 and 10 in 898. Every page's stream ends with its end-of-information code and yields **exactly** `w × h` pixels. Disposal use: 1027 pages none, 1116 leave, 1222 restore to background, 44 restore to previous. 609 pages carry a transparent index, 721 a zero delay, and 789 have no control extension at all. 78 files keep a background colour index **past** the end of the global table (e.g. 255 in a 32-entry table), 190 carry a `NETSCAPE2.0` application extension, none a plain-text extension, one a non-zero pixel aspect ratio, and 1631 of 1632 end with the `3B` trailer. Every page's rectangle lies inside its logical screen and no page is zero-sized. Inside the six TK2-era games the reachable GIFs are LittleMan's **29**, all in `Bitmap/`, all single-page (GIF87a and GIF89a, 3×1 to 608×358, mostly 20×20 sprites); **no animated GIF exists anywhere in a game tree** — all 185 multi-page files are site banners, forum avatars and logos (the largest 77 pages of 80×60).

- Given a GIF whose walk ends after its last page with no `3B` trailer, when decoded, then the picture is returned with a warning and no error.
- Given a project holding a `.gif`, when `pnpm dump <project>` runs, then the file is listed as parsed with its dimensions (not skipped), and `pnpm dump:check` still matches `golden/legacy-corpus.json` untouched.
- Given a still GIF through `decodeTexture`, when decoded, then it is exactly the first page of `decodeGif`'s model, and the PNG, JPEG and BMP decoders still pass unchanged.
- Given ticket 16.9's fixtures, when the six TK2 games are dumped, then their GIFs parse and their digests are recorded there — not here.

## Implementation Notes

- **Doc-first, and why it is a prerequisite, not a courtesy.** G7 rule 4 (`docs/guardrails.md:125`) requires the layout to exist in `docs/` before code implements it, and the archive evidence behind every rule lives outside the repository. GIF87a/GIF89a is a public format, so the section is authored rather than extracted: the layout is public knowledge, and the composition rules, the transparency of uncovered area, the refusal set and the product limit are our own rules, marked **Reawakened rule** per ADR 0007 decision 2. The evidence paragraph cites the archive files by count, the way ADR 0007 decision 3 asks.
- **Two surfaces, one boundary.** `decodeTexture` keeps its exact contract — straight RGBA, first row first, no key applied — and for a GIF returns the **first page**, decoded without walking the later pages, so the dump and the rasteriser pay for one page. `decodeGif` is the animation path's entry and exists because `decodeTexture` cannot express pages and delays (`docs/spec/formats/README.md:118` demands them, E-54 names them). AD-28's Check line (`architecture-rpgtoolkit-reawakened.md:328`) says "exports `decodeTexture` and its result type only", so the spine is amended in the same change, in its own one-line commit, for the same reason AD-8 was (`64dc26b4`). AD-22's rule that a package exports one entry is untouched: both functions are exported from `src/formats/image/index.ts` and no other package can reach `gif.ts`, `png.ts`, `jpeg.ts` or `bmp.ts`.
- **The reading of R-10 at this layer, and the alternative.** The decoded frames are all the **logical screen** size, so "the size comes from the first page" holds for every page and the animation gets the one `width`/`height` an `.anm` stores (`docs/spec/formats/animation.md:7-19`); 10 archive files have a first page smaller than the screen, where clipping to page 1's rectangle would throw away pixels of later pages. `transparent` is the first page's transparent index's colour when that page declares one, else the background colour when the index is within the global table, else magenta — R-10's own words put the background colour as the fallback and magenta after it, and the transparent index first is what makes the animation's key colour the one the art's transparent pixels already carry. The alternative (background colour first) is a one-line change if the owner prefers it. A background index past the table is **not** a refusal: 78 real files do it, so it means "no background colour" and the magenta fallback applies.
- **Delays are the file's own.** A page's `delay` is its control extension's hundredths ÷ 100 seconds, and 0 when it has none; the reader does not invent the 10-hundredths substitute some clients use, because R-10's consumer takes one delay from the first page and the animation model owns that decision. 721 archive pages store a zero delay and 789 have no control extension, so both cases are real, not hypothetical.
- **Composition, and why transparency rather than the background colour.** A frame is the canvas after its page is drawn: pages are drawn at their offsets, disposal leaves it (0, 1), clears the page's rectangle (2) or restores the canvas as it was before the page (3). Uncovered screen area and a cleared rectangle are transparent, not the background colour, because an animation's frames are drawn over the game rather than onto a background — and because the RGBA contract has no place for a background (the colour a game tests is the `key` of a `blit`, AD-3, applied to these pixels).
- **No new dependency.** `packages/core/dependency-allowlist.json` holds `["fflate"]` and `pnpm lint` fails when `core`'s runtime dependencies differ (`tools/check-core-deps.mjs:1-59`). A GIF reader is table-driven integer work of a few hundred lines, so nothing is added: `omggif` appears only as a *candidate* in `epic-legacy-formats/discovery/decoders-and-containers.md:35`, its sibling `gifuct-js` was already rejected there for `Math.pow` (`:36`), and a hand-written decoder keeps the determinism surface ours (G3 bans all but the listed `Math` members; LZW needs none of them).
- **The 58-file digest clause is 16.9's.** This entry cannot gate on the six TK2 games' GIFs: `tools/fixtures/sources.json` pins only `demo` and `Basic`, whose pictures are JPEG and PNG only (`epic-legacy-formats/discovery/corpus-inventory.md:16`), `golden/legacy-corpus.json` holds no `.gif`, and 16.9 owns the six games' fetch source and hashes. As 16.11's plan did for BMP, this entry proves the decoder on committed authored fixtures, hand-built arrays and a throwaway cross-check against the archive's 1632 real files, and 16.9 records the corpus digests. If the owner rules otherwise, the entry gains the fixture work and this plan is amended.
- **A consequence worth naming.** Once `gif` is a registered extension, `classify` (`packages/runner-headless/src/dump/formats.ts:126-136`) routes every project GIF to the registry, so a GIF we refuse becomes a **failure** rather than a skip. That is §10.4's "refuse rather than approximate" applied to the dump; the alternative (keep skipping unsupported variants) would hide a damaged game file. The refusal set is set from the census above so that no real file in the archive would flip: every file but one ends with the trailer (a warning), none has a zero-size page, none leaves the screen, none uses a code size outside 2 to 8, and every stream ends on the exact pixel count.
- **What 16.8, 16.9 and 16.10 inherit.** 16.8 ("Register the TK2 decoders") has nothing to do for GIF: the image decoder is registered by 2.3 and this entry adds `gif` to it. 16.9 records the six games' GIF digests. 16.10's sweep picks up anything the review defers. 16.11 (BMP) touched the same three places and is landed at this plan's baseline revision, so no rebase is expected; if another entry edits `image/index.ts`, the registry's `image` entry or the dump's skip table first, re-read those three files before editing.

## Design Notes

Order of work: the docs section first (it fixes the field tables, the composition rules, the refusal wording and R-10's reading, which the code and the tests quote); then `gif.ts` against hand-built byte arrays and the archive's real files in a throwaway check; then the authored fixtures with the generator's own LZW encoder; then the index/model/registry wiring and the dump's skip-row removal, so `pnpm dump` shows a `.gif` parsed; then the spine's AD-28 line and the tests; then `pnpm dump:check` last, where an unchanged golden is the proof that nothing about the 3.1 corpus moved.

Two implementation details worth settling before writing code, because they drive the shape of `gif.ts`:

- **Where a located error points inside an LZW stream.** A code is a bit range of the concatenated sub-blocks, so the decoder keeps an index of `(fileOffset, length)` per sub-block and maps a code's first bit back to the byte it came from; a refusal (an unknown code, a wrong pixel count, no end-of-information code) then names that byte. The hand-built tests assert the offset, so the mapping cannot rot.
- **The sub-block chain is the boundary.** A sub-block whose declared length runs past the end of the file, or a chain that never reaches its zero terminator inside a page, is a located error at the sub-block's length byte — the same "check the count against the bytes that remain" rule the other readers keep (`docs/spec/formats/README.md:63`).

The page's `## GIF` heading is deliberately the bare word, so its anchor is `#gif` as the ticket names it; the BMP material keeps its `(`.bmp`)` heading text so `#windows-bitmap-bmp` survives the retitle.
